## اصلاً Aether Mobile چی هست

نسخه‌ی دسکتاپ Aether دو تکه کار می‌کند: اول **Aether engine** اجرا می‌شود و روی <span dir="ltr">`127.0.0.1:1819`</span> یک پراکسی SOCKS5 بالا می‌آورد، بعد تازه شما باید آن آدرس را بدهی به یک اپ دوم مثل v2rayNG تا ترافیک واقعاً از آن رد شود.

**Aether Mobile آن تکه‌ی دوم را حذف کرده.** اینجا انجین، هسته‌ی تونل و VPN سیستم همگی داخل یک APK کنار هم بالا می‌آیند:

1. خود اپ همان Aether engine را داخلی اجرا می‌کند و SOCKS5 را روی <span dir="ltr">`127.0.0.1:1819`</span> باز می‌کند.
2. بعد یک **`VpnService`** واقعی اندرویدی بالا می‌آورد، یعنی یک TUN سیستمی که کل ترافیک گوشی را می‌گیرد.
3. بعد یک **هسته‌ی تونل داخلی** (`hev-socks5-tunnel` یا وقتی فیلتر per-app روشن باشد، بریج userspace خود اپ) هر بسته را از TUN برمی‌دارد و می‌فرستد داخل همان SOCKS5 لوکال.

نتیجه: کل زنجیره‌ی *Aether + v2rayNG* می‌شود یک اپ و یک دکمه.

```text
┌──────────────┐
│  اپ‌های شما  │  کروم، تلگرام، بازی، همه‌چی
└──────┬───────┘
       │  بسته‌های خام IP
┌──────▼───────────────────────┐
│  Android VpnService (TUN)    │  داخلی · MTU پیش‌فرض 1280
│  مسیر پیش‌فرض IPv4 و IPv6    │  اسپلیت‌تانل و بلاک per-app اینجا اعمال می‌شود
└──────┬───────────────────────┘
       │
┌──────▼───────────────────────┐
│  هسته‌ی تونل                 │  hev-socks5-tunnel به‌صورت پیش‌فرض
│                              │  یا بریج userspace فیلترشونده
└──────┬───────────────────────┘
       │  SOCKS5
┌──────▼───────────────────────┐
│  127.0.0.1:1819              │  پراکسی لوکال انجین Aether
└──────┬───────────────────────┘
       │
┌──────▼───────────────────────┐
│  Aether engine (core 1.7.0)  │  WireGuard / MASQUE-QUIC · TLS 1.3 · ECH
│  اسکن، Obfuscation، Rules    │  Fragmentation · Zero Trust · Routing
└──────┬───────────────────────┘
       │  قبل از خروج از گوشی رمزنگاری می‌شود
┌──────▼───────────────────────┐
│  لبه‌ی Cloudflare WARP       │  anycast، یعنی اپراتور شما تعیین می‌کند کدام دیتاسنتر جواب بدهد
└──────┬───────────────────────┘
       │
    اینترنت
```

**توی این زنجیره هیچ سروری که ما رانش کرده باشیم وجود ندارد.** هر چیزی که قبل از WARP edge می‌بینی روی خود گوشی تو اجرا می‌شود؛ آن طرفش هم زیرساخت عمومی Cloudflare است.

### اتصال یک مسیر چهار مرحله‌ای دارد، و اپ دقیقاً نشان می‌دهد کجای کار هستی

| مرحله | چه اتفاقی می‌افتد | چرا ممکن است طول بکشد |
|---|---|---|
| **Engine** | پروسه‌ی نیتیو انجین بالا می‌آید و اسکن رنج‌های WARP را شروع می‌کند. | بسته به Scan mode، از حدود ۶۰ ثانیه در Turbo تا حدود ۳۶۰ ثانیه در Ironclad. |
| **Tunnel** | پورت SOCKS5 لوکال باز می‌شود، TUN و هسته‌ی تونل بالا می‌آیند. | معمولاً چند ثانیه. |
| **Verify** | چهار چک سلامت انجام می‌شود: پورت لوکال، هندشیک، دسترسی واقعی به اینترنت، و تشخیص IP خروجی. | برای همین «Connected» اینجا یعنی واقعاً وصل شده‌ای. |
| **Ready** | نشست پذیرفته می‌شود، متر ترافیک زنده می‌شود، IP خروجی + پرچم + Latency نمایش داده می‌شود. | — |

یک تایمر هم موقع اتصال جلوی چشمت می‌دود، که اسکن طولانی Ironclad با هنگ واقعی یکی به نظر نرسد.

### Smart Auto: قبل از انتخاب پروتکل، خود اپ شبکه‌ات را بو می‌کشد

وقتی **Protocol = Smart** باشد، اپ شانسی انتخاب نمی‌کند. قبل از اینکه انجین را بالا بیاورد، مسیر واقعی شبکه‌ی تو را موازی بررسی می‌کند:

- **سلامت UDP** با DNS واقعی به <span dir="ltr">`1.1.1.1`</span> و <span dir="ltr">`8.8.8.8`</span>
- **فیلترینگ مبتنی بر SNI** با یک TLS handshake کامل به Cloudflare
- **Latency TCP** روی رنج‌های WARP تا انجین از همان اول سراغ رنج‌های جواب‌گو برود
- **کانتکست اپراتور** مثل نام، کد کشور و نوع شبکه، بدون هیچ مجوز اضافه

بعد شبکه را در یکی از این دسته‌ها می‌گذارد: **Open**، **SNI filtering**، **UDP throttling** یا **Hostile**. بعد بر اساس همان، یک نردبان از *پروتکل + Obfuscation + Fragmentation/ECH + رنج‌های زنده* می‌چیند و یکی‌یکی امتحان می‌کند. اولین استراتژی‌ای که از چهار مرحله‌ی Verify رد شود، قفل می‌شود و برای reconnectهای بعدی هم استفاده می‌شود. همه‌ی این تصمیم‌ها هم داخل Diagnostics لاگ می‌شوند. یعنی اگر خواستی ببینی اپ چرا فلان انتخاب را کرده، حدس نمی‌زنی، می‌خوانی.

اگر خودت **پروتکل را دستی** انتخاب کنی، اپ یواشکی عوضش نمی‌کند. همان پروتکل را با بودجه‌ی کامل اسکن امتحان می‌کند و اگر نشد، **همان پروتکل** را با ضد DPI قوی‌تر دوباره تست می‌کند.

### چطور پایدار می‌ماند

- یک **watchdog** هر ۳۰ ثانیه انتها به انتهای تونل را چک می‌کند و فقط وقتی سه بار پشت سر هم شکست ببیند انجین را ری‌استارت می‌کند. یعنی یک تلوتلو خوردن کوتاه شبکه، نشست سالم را الکی نمی‌کشد.
- **supervisor** به‌جای polling مستقیم روی پروسه‌ی انجین منتظر می‌ماند، پس هم مصرف CPU کمتر است، هم کرش سریع‌تر تشخیص داده می‌شود.
- **Smart Reconnect** تا سقفی که خودت تعیین می‌کنی خودکار reconnect می‌کند.
- اگر **VPN service** را سیستم بکشد، با همان پروفایل واقعی تو برمی‌گردد، نه با تنظیمات کارخانه.

## داده‌ی شما دقیقاً کجا می‌رود

سوال درست و حسابی همین است: *«یه VPN رایگان بدون لیست سرور، پس سرورش مال کیه و چه کسی ترافیکم را می‌بیند؟»*

جواب کوتاه و بی‌فیلم:

- **هیچ واسطه‌ی مخفی‌ای وسط نیست.** Aether ترافیکت را از VPS شخصی کسی رد نمی‌کند. انجین دستگاه تو را وصل می‌کند به **شبکه‌ی Cloudflare WARP**، همان زیرساخت جهانی معروف پشت 1.1.1.1 / WARP. مقصد همین است: لبه‌ی عمومی Cloudflare.
- **رمزنگاری روی خود گوشی انجام می‌شود.** ترافیکت با WireGuard یا MASQUE/QUIC **قبل از خروج از دستگاه** رمز می‌شود و تازه داخل شبکه‌ی Cloudflare برای رفتن به سایت مقصد باز می‌شود. ISP یا وای‌فای اطراف فقط نویز رمزنگاری‌شده می‌بیند.
- **توسعه‌دهنده‌ها هیچ سروری ران نمی‌کنند و چیزی هم تحویل نمی‌گیرند.** نه اکانت، نه SDK آنالیتیکس، نه کرش‌ریپورت ارسالی، نه phone-home. چیزی برای فرستادن نیست، جایی هم برای فرستادنش نیست.
- **Country picker ندارد، چون صادقانه نمی‌توانست داشته باشد.** آدرس‌های WARP از نوع **anycast** هستند، یعنی یک IP از چند دیتاسنتر همزمان announce می‌شود و این مسیر اپراتور تو است که تعیین می‌کند کدام دیتاسنتر جواب بدهد، نه اپ. پس منوی کشور فقط یک برچسب الکی می‌شد، برای همین حذف شد.
- **می‌توانی خودت راستی‌آزمایی کنی.** هم اپ و هم انجین متن‌بازند: [این مخزن](https://github.com/MrMatin0/Aether) و [CluvexStudio/Aether](https://github.com/CluvexStudio/Aether). APKها هم عمومی توسط GitHub Actions از روی همین سورس ساخته می‌شوند.
- **اما بخش صادقانه‌ی ماجرا:** مثل هر VPN دیگری، اپراتور شبکه‌ی خروجی یعنی اینجا Cloudflare، از نظر فنی می‌تواند ترافیکی را که از آن خارج می‌شود ببیند ([سیاست حریم خصوصی WARP](https://www.cloudflare.com/application/privacy/)). البته سایت‌هایی که با HTTPS باز می‌کنی همچنان end-to-end رمز هستند. اگر مدل تهدیدت Cloudflare را قبول ندارد، هیچ ابزار WARP-baseی برایت مناسب نیست، این هم یکی از همان‌هاست.

> **خلاصه:** <span dir="ltr">`گوشی تو → (رمزنگاری‌شده) → Cloudflare WARP → سایت مقصد`</span>. توسعه‌دهنده اصلاً وسط این مسیر نیست.

## اپ، صفحه به صفحه

در نسخه‌ی ۱.۳.۰ ساختار قدیمی drawer همبرگری + bottom sheet تکراری کنار گذاشته شد و جایش را داد به **سه تب پایین صفحه**، با دکمه‌ی اصلی اتصال دقیقاً بالای همان نوار. یعنی جایی که شست آدم واقعاً بهش می‌رسد.

### ۱. Connection

این‌جا بخش اصلی کار است:

- **حلقه‌ی اتصال** برای وصل و قطع، با haptic feedback
- **Phase pipeline + تایمر** موقع وصل شدن
- **Traffic panel** برای سرعت و مجموع آپلود/دانلود
- **Info ledger** برای IP خروجی، پرچم، Protocol، Endpoint و Latency زنده

آن Latency هم الکی نیست: یک TCP ping واقعی به <span dir="ltr">`1.1.1.1:53`</span> از داخل خود تونل است، نه یک عدد تزئینی.

### ۲. Settings

ترتیب این بخش عمداً بر اساس «احتمال اینکه برای همین آمده باشی این‌جا» چیده شده:

1. **Language**: اگر اپ به زبانی باشد که نمی‌فهمی، هیچ‌کدام از بخش‌های بعدی به دردت نمی‌خورند.
2. **Engine settings**: همه‌چیزهایی که تعیین می‌کنند اتصال اصلاً بگیرد یا نه.
3. **Saved setups**: ترکیب تنظیماتی که جواب داده، با یک ضرب دوباره اعمال می‌شود.
4. **Automation**: چه وقت خود اپ خودش وصل شود و چه چیزی را نگه دارد.
5. **Session history**: بعد از اتمام نشست‌ها چه اتفاقی افتاده.
6. **Share VPN** و **About**: چیزهایی که هر روز سراغشان نمی‌روی.

> تنظیماتی که آرگومان‌های انجین را عوض می‌کنند، **وسط نشست قفل می‌شوند**. دلیلش هم ساده است: انجین آرگومان‌ها را موقع لانچ می‌خواند، نه وسط کار. پس disconnect کن، تنظیم کن، دوباره connect.

### ۳. Diagnostics

کنسول کامل انجین. یک ring buffer محدود به ۸۰۰ خط، آپدیت UI با سرعت کنترل‌شده، نوشتن روی دیسک به‌صورت batch، و فایل لاگ چرخشی با سقف ۵۱۲ کیلوبایت. فقط وقتی این صفحه باز است واقعاً subscribe می‌شود. یعنی هم مصرفش معقول است، هم اگر باگ دیدی لاگ درست‌ودرمان برای گزارش داری.

| **TLS groups** | مثل <span dir="ltr">`X25519:P-256`</span> | گروه‌های curve پیشنهادی را محدود می‌کند و fingerprint TLS را عوض می‌کند. |
| **MTU** | 1280 · 1380 · 1420 · 1500 · 8500 | MTU اینترفیس TUN. برای شبکه‌های موبایل ایران و DPI شدید، **1280** بهترین نقطه‌ی شروع است. |

## پریست‌ها و انتقال تنظیمات

این بخش دقیقاً دو درد را حل می‌کند.

**اولی:** تنظیماتی که روی یک شبکه جواب می‌دهند، لزوماً روی شبکه‌ی بعدی همان نیستند. اگر هر بار بخواهی از حفظ دوباره ۸ تا گزینه را سرهم کنی، خیلی زود خسته می‌شوی. برای همین پریست داری: اسم بده، ذخیره کن، هر وقت خواستی یک‌ضرب apply کن.

**دومی:** انتقال یک کانفیگ جواب‌داده به گوشی دیگر. قبلاً باید تک‌تک فیلدها را بگویی یا عکس بفرستی. حالا یک متن قابل کپی است:

- **Copy config** پروفایل فعلی را می‌گذارد روی کلیپ‌بورد
- **Paste config** متن را validate می‌کند و اگر سالم بود اعمالش می‌کند

نکته‌ی مهم: چون export از همان codec پروفایل می‌گذرد که سرویس VPN استفاده می‌کند، **secretهای Zero Trust ذاتاً از متن خروجی حذف می‌شوند**. یعنی نمی‌توانی شانسی secret سازمانت را بفرستی توی یک گروه.

Apply کردن پریست هم فقط وقتی ممکن است که نشست فعال نباشد. دلیلش همان است: انجین وسط کار آرگومان‌های تازه را نمی‌خواند.

## اتوماسیون

سه سوییچ که سه سوال پرتکرار را جواب می‌دهند: «چرا وقتی اپ را باز کردم خودش وصل نشد؟»، «چرا بعد از ریبوت بالا نیامد؟» و «اصلاً چه چیزی از نشست‌ها نگه می‌داری؟»

| سوییچ | پیش‌فرض | اثر |
|---|---|---|
| **Connect when the app opens** | خاموش | با cold launch شروع می‌کند به وصل شدن. |
| **Connect after reboot** | خاموش | بعد از روشن شدن دستگاه دوباره وصل می‌شود. البته به شرطی که مجوز VPN از قبل داده شده باشد. |
| **Keep session history** | **روشن** | نشست‌های تمام‌شده را روی همین دستگاه ثبت می‌کند. خاموشش کنی، چیزی ثبت نمی‌شود. |

پایینش هم دو دکمه هست که مستقیم می‌برندت به تنها دو صفحه‌ی سیستمی‌ای که واقعاً روی زنده‌ماندن VPN در پس‌زمینه اثر دارند: **Always-on VPN** و **Battery optimization**. اپ نمی‌تواند به‌جایت این‌ها را toggle کند، پس به‌جای نصیحتِ مبهم، مستقیم پرتت می‌کند همان‌جا. اگر رام گوشی صفحه را نداشته باشد یا اسمش را عوض کرده باشد، پیام درست می‌بینی، نه کرش الکی.

## تاریخچه‌ی نشست‌ها

متر ترافیک زنده با تمام شدن نشست می‌میرد. نتیجه؟ سوال‌های مهمی مثل «این اتصال چهار ساعت دوام آورد یا چهار دقیقه؟» و «دیشب چقدر اینترنت مصرف کرد؟» بی‌جواب می‌ماندند.

History برای هر نشست این‌ها را نگه می‌دارد:

- زمان شروع
- مدت زمان
- حجم دانلود
- حجم آپلود

بعلاوه یک خط جمع کل. روی سیم‌کارت حجمی، همان جمع کل از همه مهم‌تر است.

این داده‌ها فقط **لوکال** و داخل فضای خصوصی خود اپ نگه‌داری می‌شوند، پاک‌کردنشان یک ضرب است، و کلاً می‌توانی با یک سوییچ خاموششان کنی. اعداد هم حتی در حالت فارسی، LTR و monospace نمایش داده می‌شوند که الگوریتم BiDi خراب‌کاری نکند.

## تایل، ویجت و نوتیفیکیشن

هر سه از یک هوک تغییر وضعیت داخل VPN service تغذیه می‌شوند. یعنی قرار نیست ویجت یک چیز بگوید و نوتیفیکیشن یک چیز دیگر.

**Quick Settings tile**: یک بار پنل نوتیفیکیشن را پایین بکش، روی edit یا آیکن مداد بزن، تایل **Aether** را بکش داخل active tiles. بعدش هر وقت خواستی از همان‌جا connect یا disconnect کن.

**ویجت صفحه‌ی خانه**: وضعیت زنده + اتصال/قطع با یک لمس. مقدار <span dir="ltr">`updatePeriodMillis=0`</span> است، یعنی تایمر دوره‌ای برای بیدار کردن دستگاه ندارد و فقط وقتی وضعیت اتصال عوض شود repaint می‌شود.

> اولین اتصال را باید یک بار از داخل خود اپ شروع کنی تا اندروید دیالوگ مجوز VPN را نشان بدهد. بعد از آن، اگر اپ از قبل باز باشد، تایل و ویجت هم می‌توانند مجوز را دوباره درخواست کنند.

## اشتراک‌گذاری VPN با لپ‌تاپ یا گوشی دیگر

گوشی تو می‌تواند برای بقیه‌ی دستگاه‌های روی همان وای‌فای یا روی hotspot خودش نقش **gateway** بازی کند.

1. اول VPN را داخل Aether وصل کن.
2. برو **Settings → Share VPN** و **Share on this network** را روشن کن.
3. یکی از این دو آدرس را کپی کن:

| نوع | آدرس | کجا باید واردش کنی |
|---|---|---|
| **HTTP proxy** | <span dir="ltr">`<phone-ip>:10811`</span> | داخل system proxy دستگاه مقصد. ویندوز: Settings → Network → Proxy → Manual. macOS: Wi-Fi → Details → Proxies → Web/Secure Web Proxy. اندروید/iOS: Wi-Fi → Modify network → Proxy → Manual. |
| **SOCKS5 proxy** | <span dir="ltr">`<phone-ip>:10810`</span> | برای اپ‌ها و مرورگرهایی که SOCKS را می‌فهمند، مثل Firefox یا Telegram. |

> ⚠️ تا وقتی sharing روشن است، **هر کسی روی آن شبکه** می‌تواند از آن پراکسی استفاده کند. پس فقط روی شبکه‌ای روشنش کن که بهش اعتماد داری. بهترین گزینه hotspot خودت است. با disconnect شدن VPN هم sharing خودکار قطع می‌شود.

**چرا 10810 و 10811؟** چون 10808 و 10809 پیش‌فرض v2rayNG هستند، و این تداخل قبلاً واقعاً دردسر بود. Aether حالا علاوه بر عوض کردن پورت‌ها، قبل از bind کردن همسایه‌های معروف مثل v2rayNG، Clash، Psiphon و Privoxy را هم چک می‌کند و اسم همان مزاحم را توی خطا می‌گوید.

## زبان و تایپوگرافی

Aether رابط کامل **فارسی** و **انگلیسی** دارد و از نسخه‌ی ۱.۳.۰ به بعد انتخاب زبان **داخل خود اپ** انجام می‌شود. یعنی یک pill کوچیک بالای صفحه، و تمام. قبلاً برای دیدن ترجمه‌ی فارسی باید زبان کل گوشی را عوض می‌کردی، که واقعاً کار مسخره‌ای بود.

- روی **Android 13 به بالا** از API رسمی زبانِ per-app خود سیستم استفاده می‌شود. یعنی اکتیویتی‌ها، نوتیفیکیشن VPN، Quick Settings tile و حتی صفحه‌ی app info خود اندروید، همگی همان زبان را می‌فهمند.
- روی **Android 8 تا 12** چنین APIای وجود ندارد، پس انتخاب زبان ذخیره می‌شود و روی resourceهای اکتیویتی اعمال می‌شود، و جهت چیدمان برای فارسی هم برمی‌گردد RTL.

فونت اپ **[Vazirmatn](https://github.com/rastikerdar/vazirmatn) نسخه‌ی 33.003** است و مستقیم داخل APK باندل می‌شود. دلیلش روشن است: دانلود فونت از Google Fonts در زمان اجرا یعنی وابستگی به شبکه و Play Services، و این اپ دقیقاً برای شرایطی ساخته شده که ممکن است هیچ‌کدامشان در دسترس نباشند. فونت باندل‌شده همیشه بالا می‌آید.

برای فارسی line-leading کمی بازتر شده، چون ink extent حروف فارسی در Vazirmatn با همان spacing فشرده‌ی لاتین خوب نمی‌نشیند. یک قانون هم برای اعداد وجود دارد: **متن عادی از رقم‌های همان زبان پیروی می‌کند، ولی readoutهای فنی نه.** یعنی latency، traffic، duration و timer همیشه با رقم لاتین، LTR و monospace نمایش داده می‌شوند. نصفه‌نیمه بودن در این بخش فقط آشغال است.

## طراحی Carbon & Signal

در نسخه‌ی ۱.۳.۰ ظاهر قدیمیِ سرمه‌ای + آبی نئونی کنار گذاشته شد. هم شبیه همه‌ی اپ‌های مشابه بود، هم اصلاً معنی نداشت. آبی همزمان نقش «وصل شدی»، لینک، آیکن و آیتم انتخاب‌شده را بازی می‌کرد. خب این طراحی نیست، شلوغ‌کاری است.

اینجا منطق جدید این است:

- **رنگ‌های خنثی، Carbon هستند**: مشکی مطلق و سفید مطلق نداریم. مشکی تخت روی OLED زشت می‌شود و سفید خالص توی دارک‌مود چشم را می‌زند.
- **رنگ‌ها معنایی‌اند، نه تزئینی**: یعنی رنگ فقط وقتی استفاده می‌شود که معنی داشته باشد.

| توکن | رنگ | معنی |
|---|---|---|
| **Signal** | <span dir="ltr">`#A9E34B`</span> | یعنی محافظت شدی، اتصال امن است. |
| **Ember** | <span dir="ltr">`#E9B44C`</span> | یعنی در حال کار است: اتصال، اسکن، Verify. |
| **Clay** | <span dir="ltr">`#E8674A`</span> | یعنی خطا یا شکست. |
| **Carbon 00 → 40** | <span dir="ltr">`#090B08` → `#333D2B`</span> | بک‌گراند، سرفیس، hairline، outline. |
| **Chalk** | <span dir="ltr">`#EDF2E6`</span> / <span dir="ltr">`#A6B09B`</span> / <span dir="ltr">`#6C7663`</span> | متن اصلی، فرعی و کم‌رنگ. |

**Dynamic color یا Material You عمداً حذف شد.** چون والپیپرنباید تعیین کند رنگ «امن» همان نارنجی‌ای شود که جای دیگر برای «خطا» استفاده می‌شود. کنتراست هم تصادفی می‌شد و بعضی‌وقت‌ها hairlineها و کنسول لاگ تقریباً گم می‌شدند. برای ابزار ضد سانسور، هویت بصری ثابت مهم است. اگر هر گوشی یک شکل رندرش کند، اسکرین‌شات‌های گزارش باگ به درد لای جرز می‌خورند.

یک چیز دیگر هم حذف شد: **aurora animation**. سه گرادیان بزرگ تمام‌صفحه دائم پشت UI رندر می‌شدند و بی‌خودی GPU/CPU می‌خوردند. الان بک‌گراند ثابت است و بودجه‌ی فریم جایی می‌رود که باید برود: خود رابط.

## نصب و آپدیت

### نیازمندی‌ها

- **اندروید 8.0 (API 26) به بالا**
- مجوز استاندارد **VPN** از طرف خود اندروید
- مجوز نوتیفیکیشن برای نمایش وضعیت دائمی
- بدون نیاز به Play Services، بدون نیاز به root، بدون نیاز به اکانت

### کدام APK مناسب است؟

| فایل | مناسب چه گوشی‌ای است؟ |
|---|---|
| `Aether-1.3.0-arm64-v8a.apk` | تقریباً همه‌ی گوشی‌های جدید ۶۴ بیتی ARM |
| `Aether-1.3.0-armeabi-v7a.apk` | گوشی‌های قدیمی‌تر یا ضعیف‌تر ۳۲ بیتی |
| `Aether-1.3.0-universal.apk` | **اگر مطمئن نیستی، همین را بگیر** |

### برای آپدیت باید uninstall کنم؟

اگر APK جدید و قدیم با **یک امضای یکسان** ساین شده باشند، اندروید آپدیت را روی همان قبلی نصب می‌کند.

- **از v1.1.0 به بعد**: نه، فقط دانلود و نصب کن. روی نسخه‌ی قبلی می‌نشیند.
- **اگر از v1.0.0 یا قدیمی‌تر می‌آیی**: یک بار آخر uninstall لازم است، چون آن نسخه‌ها با کلید موقت ساین شده بودند.

این موضوع الان با build enforce می‌شود، نه با دعا. CI اثرانگشت SHA-256 امضاکننده را از هر APK در می‌آورد و با مقدار pin‌شده مقایسه می‌کند. اگر امضا عوض شود، بیلد fail می‌شود و APK خراب منتشر نمی‌شود.

### آپدیت درون‌برنامه‌ای عمداً حذف شده

> برای امنیت کاربر، شفافیت کامل و اینکه مطمئن باشی کدی که می‌گیری همان چیزی است که باید بگیری، قابلیت آپدیت مستقیم از داخل اپ از نسخه‌ی ۱.۲.۲ حذف شد. از آن به بعد همه‌ی آپدیت‌ها فقط از صفحه‌ی رسمی Releases گیت‌هاب می‌آیند.

یعنی چه چیزهایی حذف شدند؟ downloader پس‌زمینه، کارت «آپدیت موجود است»، `FileProvider` مربوط به نصب APK، و مهم‌تر از همه مجوز **`REQUEST_INSTALL_PACKAGES`**. الان دیگر **هیچ مسیر کدی داخل Aether وجود ندارد که برود یک باینری تازه بگیرد و اجرا کند**.

## اگر خواستی خودت بیلد بگیری

لازم نیست Android Studio داشته باشی. GitHub Actions همه‌چیز را می‌سازد.

1. این سورس را fork کن یا بریز داخل یک ریپو
2. برو تب **Actions** و اگر لازم بود workflowها را فعال کن
3. هر push به `main` بیلد می‌گیرد. برای اینکه فایل‌های release ساخته شوند، تگ بزن:
   ```bash
   git tag v1.3.0
   git push origin v1.3.0
   ```
4. وقتی کار تمام شد، داخل **Releases** سه APK می‌بینی. متن «What's new» هم از `.github/release-notes.md` می‌آید، پس با نسخه هماهنگش کن.

### اگر می‌خواهی با کلید خودت ساین کنی

| Secret | معنی |
|---|---|
| `KEYSTORE_BASE64` | فایل `.jks` شما، به‌صورت base64 |
| `KEYSTORE_PASSWORD` | پسورد keystore |
| `KEY_ALIAS` | alias کلید |
| `KEY_PASSWORD` | پسورد کلید |

برای ساخت base64:

```bash
base64 -w0 my-release-key.jks > keystore.txt
```

بعدش این secretها را در **Settings → Secrets and variables → Actions** بگذار. این‌ها همیشه از fallback keystore داخل ریپو اولویت بالاتری دارند. برای بیلد لوکال هم `keystore.properties` جواب می‌دهد. نمونه‌اش را در `keystore.properties.example` و توضیح کامل را در [`docs/SIGNING.md`](docs/SIGNING.md) ببین.

> ♻️ **ریپو را عوض نکن، کلید را هم گم نکن.** fallback key پایدار داخل `.github/ci-keystore.jks.b64` همان چیزی است که باعث می‌شود نسخه‌ی جدید روی نسخه‌ی قبلی نصب شود.
>
> 🔒 ولی حواست باشد: keystore داخل ریپوی عمومی، خودش عمومی است. این فقط **قابلیت آپدیت** را حفظ می‌کند، نه **اصالت** را. برای توزیع جدی، برو سراغ secretهای واقعی خودت.

### بخش‌های نیتیو چطور ساخته می‌شوند

بالادستی Aether باینری اندرویدی منتشر نمی‌کند، پس CI آن‌ها را از سورس می‌سازد. blob نیتیو و فونت‌ها هم داخل ریپو commit نمی‌شوند.

| اسکریپت | وظیفه |
|---|---|
| `scripts/fetch-natives.sh` | سورس `hev-socks5-tunnel` و Aether engine را می‌گیرد |
| `scripts/build-natives.sh` | `hev` را با `ndk-build` و انجین را با `cargo-ndk` برای `arm64-v8a` و `armeabi-v7a` می‌سازد |
| `scripts/fetch-fonts.sh` | پنج وزن موردنیاز Vazirmatn را می‌گیرد |
| `scripts/sync-core.sh` | هسته را خودکار آپگرید می‌کند |
| `scripts/test-core-sync.sh` | کل مسیر آپگرید را آفلاین تست می‌کند |
| `scripts/purge-stale-sources.sh` | سورس‌های منسوخ فهرست‌شده در `.github/removed-sources.txt` را قبل از کامپایل پاک می‌کند |
| `scripts/core-rollback.sh` | snapshot قبلی هسته را برمی‌گرداند |

می‌توانی نسخه‌ها را با `HEV_REF`، `AETHER_REPO` و `AETHER_REF` pin کنی. CI قبل از انتشار APK را چک می‌کند و اگر coreهای نیتیو برای ABIهای لازم داخلش نباشند، release را رد می‌کند. Gradle هم روی 8.9 pin شده که toolchain زیر پایت عوض نشود.

### هسته خودش آپگرید می‌شود، ولی نه وحشیانه

بیلد مالک نسخه‌ی هسته است. در هر اجرا، `sync-core.sh` ریپوی رسمی [Aether Core](https://github.com/CluvexStudio/Aether) را چک می‌کند، با `native/aether/CORE_VERSION` مقایسه می‌کند، و اگر نسخه‌ی جدیدتر موجود باشد هسته‌ی vendored را جلو می‌برد. الان نسخه‌ی فعلی **1.7.0** است.

- **patchهای اپ کپی نمی‌شوند، rebase می‌شوند**: یعنی تغییرات خاص این اپ با یک three-way merge واقعی روی نسخه‌ی جدید اعمال می‌شوند.
- **اگر هسته‌ی جدید کامپایل نشود، ریلیز نابود نمی‌شود**: CI خودکار rollback می‌کند و با نسخه‌ی قبلی ادامه می‌دهد.
- **اگر GitHub در دسترس نباشد، باز هم بیلد نمی‌خوابد**: از همان نسخه‌ی vendored موجود استفاده می‌شود.
- **قابلیت‌های جدید پنهان نمی‌مانند**: بعد از sync، اسکریپت می‌گردد ببیند هسته چه فلگ تازه‌ای دارد که UI هنوز نشانش نمی‌دهد.
- **نسخه‌ی واقعی هسته داخل خود اپ هم دیده می‌شود**: از `native/aether/CORE_VERSION` وارد `BuildConfig.CORE_VERSION` می‌شود و در بخش About نمایش داده می‌شود.

### خلاصه‌ی وضعیت فعلی

| حوزه | وضعیت |
|---|---|
| **کلیدها و رازها** | هیچ API key، توکن، پسورد یا private key هاردکدی داخل اپ نیست. secretهای Zero Trust با Android Keystore و AES-256-GCM مهر و موم می‌شوند و فقط از طریق environment به انجین می‌رسند. |

| **لاگ** | در release، خروجی Logcat عملاً خاموش است. نه کلید، نه hostname، نه payload، نه DNS query داخل لاگ نوشته نمی‌شود. |
| **وابستگی‌ها و شبکه** | بدون SDK تبلیغات، آنالیتیکس یا crash reporting. coreهای نیتیو از سورس در CI ساخته می‌شوند. cleartext سراسری بسته است و CAهای نصب‌شده توسط کاربر trust نمی‌شوند. |
| **اعتبارسنجی ورودی** | فیلدهای آزاد مثل DNS، routing rules، rangeها و TLS groups قبل از تبدیل شدن به آرگومان validate و محدود می‌شوند. |

**کرش‌ریپورت از دستگاه بیرون نمی‌رود.** اگر برنامه fatal crash بدهد، گزارش داخل sandbox خود اپ ذخیره می‌شود، دفعه‌ی بعد بهت نشان داده می‌شود، دکمه‌ی copy دارد، و بعد از بستن حذف می‌شود. نه export شده، نه جایی ارسال می‌شود.

**یک ریسک هم شفاف اعلام شده، نه پنهان:** fallback CI keystore داخل ریپو عمومی است. این برای حفظ continuity آپدیت است، نه تضمین authenticity. پس APK را فقط از صفحه‌ی رسمی Releases بگیر و signer fingerprint را چک کن.

## عیب‌یابی

<details open>
<summary><b>می‌گوید Connected ولی چیزی باز نمی‌شود</b></summary>

از نسخه‌ی ۱.۲.۱ به بعد نباید این‌طور باشد، چون اپ تا وقتی چهار چک Verify رد نشوند اصلاً Connected نشان نمی‌دهد. اگر هنوز هم دیدی، برو Diagnostics را نگاه کن، ببین watchdog restart می‌زند یا نه، بعد Obfuscation را بگذار روی `GFW` و MTU را روی `1280`.

</details>

<details>
<summary><b>یکی دو دقیقه کار می‌کند، بعد می‌خوابد</b></summary>

ریشه‌اش در ۱.۲.۴ تا حد زیادی جمع شده: watchdog انتها به انتهای تونل را چک می‌کند و timeoutها هم بالا رفته‌اند. اگر هنوز می‌بینی، Retry limit را بیشتر کن، Quick reconnect را روشن نگه دار، و از داخل Automation برو battery optimization را برای Aether غیرفعال کن.

</details>

<details>
<summary><b>اصلاً روی شبکه‌ی من وصل نمی‌شود</b></summary>

به‌ترتیب این‌ها را امتحان کن: **Obfuscation → GFW**، بعد اگر لازم شد `Aggressive`، بعد **MTU → 1280**، بعد **TLS fragmentation روشن**، بعد **ECH روشن**، بعد **Scan mode → Ironclad**. اگر UDP دارد خفه می‌شود، **MASQUE با HTTP/2** را امتحان کن. اگر یک endpoint جواب‌گو داری، **Manual peer** بگذار تا اصلاً اسکن نکند. هر چیزی جواب داد، به‌عنوان پریست ذخیره‌اش کن که دوباره دنبال معجون نگردی.

</details>

<details>
<summary><b>خطای پورت اشغال است یا با یک اپ دیگر تداخل دارد</b></summary>

Aether برای sharing از **10810/10811** استفاده می‌کند دقیقاً برای اینکه روی پورت‌های پیش‌فرض v2rayNG نرود. تازه همسایه‌های معروف را هم شناسایی می‌کند و اسمشان را در پیام خطا می‌گوید. اپ مزاحم را ببند و دوباره تست کن.

</details>

<details>
<summary><b>وقتی صفحه خاموش می‌شود، تونل می‌میرد</b></summary>

این بیشتر از خود اپ، تقصیر سیستم و رام است. داخل **Automation** دو دکمه‌ی مستقیم برای **Always-on VPN** و **Battery optimization** داری. هر دو را درست کن.

</details>

<details>
<summary><b>بعضی تنظیمات خاکستری‌اند و تغییر نمی‌کنند</b></summary>

طبیعی است. انجین آرگومان‌ها را موقع لانچ می‌خواند. وسط نشست اگر عوضشان کنی، هیچ اثر واقعی ندارد. disconnect کن، تغییر بده، دوباره connect.

</details>

<details>
<summary><b>آپدیت نصب نمی‌شود</b></summary>

اگر از خیلی قدیم می‌آیی، مخصوصاً v1.0.0 و قبل‌تر، یک بار uninstall لازم است. از 1.1.0 به بعد باید روی همان نسخه‌ی قبلی نصب شود. اگر نمی‌شود، معمولاً یعنی APKها از دو ریپوی مختلف با دو keystore مختلف آمده‌اند.

</details>

<details>
<summary><b>مشکل دیگری دارم، چطور درست گزارشش کنم؟</b></summary>

`Core log level` را بگذار روی `debug`، مشکل را بازتولید کن، از صفحه‌ی Diagnostics لاگ را کپی کن، و همراه نسخه‌ی اندروید، مدل گوشی، اپراتور/ISP و تنظیماتی که استفاده کرده‌ای issue باز کن. لاگ کلید و payload و hostname ندارد، پس از این بابت خیالت راحت باشد.

</details>

## سوال‌های پرتکرار

**رایگان است؟ کجای کارش مشکوک است؟**
رایگان است، AGPL-3.0 است، تبلیغ و آنالیتیکس و اکانت ندارد. بخش حساس ماجرا همان است که بالا گفتیم: خروجی‌ات روی شبکه‌ی WARP کلادفلر است و کلادفلر از نظر فنی می‌تواند ترافیک خروجی را ببیند.

**چرا لیست کشور یا سرور ندارد؟**
چون اگر داشت، بیشترش نمایش بود تا واقعیت. WARP anycast است و منوی کشور واقعاً نمی‌تواند تو را به یک کشور خاص پرت کند.

**یعنی اصلاً نمی‌شود کشور خروجی را انتخاب کرد؟**
نه به آن معنای معمول. اما می‌توانی endpoint خاص یا range خاص تعریف کنی و انجین دقیقاً همان‌ها را امتحان کند.

**root لازم دارد؟**
نه.

**بدون Google Play Services کار می‌کند؟**
بله، کامل. دلیل باندل بودن فونت هم دقیقاً همین است.

**می‌شود کنار v2rayNG استفاده‌اش کرد؟**
بله، ولی مثل هر دو VPN سیستمی دیگر، همزمان فقط یکی می‌تواند فعال باشد. تداخل پورت share هم از ۱.۲.۲ حل شده.

**لاگ نگه می‌دارد؟**
لاگ تشخیصی محدود، چرخشی و محلی است و key و hostname و payload داخلش نیست. session history هم محلی است و می‌توانی خاموشش کنی. چیزی از دستگاه بیرون نمی‌رود.

**برای Cloudflare Zero Trust شرکت هم جواب می‌دهد؟**
بله، چهار روش enrolment پشتیبانی می‌شود. بخش Zero Trust در [راهنمای کامل تنظیمات](#راهنمای-کامل-تنظیمات) را ببین.
